# saphira-llm tokenizer golden vectors, GPT-2 pre-type variant
# Captured from the REFERENCE llama_tokenize(), never from us.
#
# THIS FIXTURE EXISTS TO PROVE ONE THING: the pre-tokeniser is model
# metadata, not a constant in the tokenizer.
#
# The vocabulary, the merges, the token types and every weight are those of
# the acceptance model, byte for byte. Exactly one metadata key differs:
# tokenizer.ggml.pre = "gpt-2", added by tools/reference/make-pre-variant.
# The source model declares no `pre` at all, which is what
# tests/golden/tokenizer.txt records -- the DEFAULT fallback.
#
# Same vocabulary, one key, different tokens:
#
#   they're     gpt-2: they 're        DEFAULT: they ' ' re
#   it's        gpt-2: it 's           DEFAULT: it  ' ' s
#   1234567890  gpt-2: 123 456 7890    DEFAULT: 123 456 789 0
#   a + b = c   gpt-2: a ' +' ' b'...  DEFAULT: a ' ' + ' b' ' ' = ...
#
# The gpt-2 pre-type is the GPT-2 pattern alone. DEFAULT is that pattern
# wrapped in three more passes, and those are what split punctuation runs
# and group digits in threes. Whitespace handling lives inside the shared
# pattern, so prompts differing only in whitespace are identical under both
# -- which is itself worth recording, because it shows the two pre-types
# share a stage rather than being unrelated implementations.
#
# Phase 7's ordinary GGUF models will each declare their own `pre`. This
# fixture is the evidence that reading it is mandatory.
#
# add_special is 1: the model sets add_bos_token, so every sequence
# here begins with BOS.
